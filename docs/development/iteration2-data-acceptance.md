新增连接重载和查询方法意味着内存 DAO、手写 mock 等接口实现也需同步增加方法。

共享返回约定：查询不到单条数据返回 Optional.empty；列表不返回 null；insert 返回主键且不回填输入对象。更新通常返回行数，业务层必须按操作检查 0；例如流转更新返回 0 表示终态或成交冲突，不能继续更新物品和信用。
分页从 1 起、每页 10–100；物品默认仅检索 ON_SALE，查询全部状态需显式设置 `status(null)`。收藏保留物品当前状态，不会自动隐藏下架或已流转物品。

## 事务模板更正

**请使用模块五、六、八的事务写法，替代迭代一设计说明书第 8.3 节旧示例。**
旧示例只捕获 SQLException，随后在 finally 中 `setAutoCommit(true)`。当前 DAO 把 SQL 故障包装为非受检 DataAccessException；若照抄旧例，异常可能跳过 rollback，切回自动提交又可能提交部分写入。

正确边界为：Service 打开一个连接，关闭自动提交，在同一连接上调用各 DAO 的 Connection 重载；正常时显式 commit，捕获 `RuntimeException | SQLException` 后显式 rollback，最后由 try-with-resources 关闭连接。回滚失败应作为 suppressed exception 保留。没有必要在关闭连接前恢复自动提交。

普通方法每次创建自己的连接，不参与另一个连接的事务。事务中的查询也要使用连接重载；不要混用普通方法判断刚写入的数据。分页的计数与列表是两次读取，需要严格同一快照时使用同连接读事务。

DAO 不自动检查操作人权限，也不替 Service 自动串联其他 DAO。Item 状态写入本身不执行完整状态机守卫，Service 必须在同一事务中读取、校验当前状态和身份，并检查更新行数。

需求 UC-07 的后置条件要求成交给双方各写一条操作日志，接入 FlowService 时应落实，不能仅因数据库有日志 DAO 就判定满足。
原设计事务表中“评价更新双方信用分”的表述应更正为“本条评价仅更新接收人信用”；双方各 +1 属于成交操作，双方互评则是两条评价各影响各自接收人。

## 成员 3 接入清单

- GUI 通过 Service 调用功能，避免直接使用 DAO 或逐步拼接多个 Service 来完成原子业务。
- 使用 PageResult 的 items/total/pageNo/pageSize/totalPages；把实体状态、当前昵称和信用投影交给界面显示。
- User 包含认证用哈希和盐，不能直接作为界面/CSV 的完整用户数据载体；先补齐不含凭据的 SessionUser 或展示对象。
- 默认库为运行目录的 `data/campus.db`；自定义路径通过启动时的 `campus.db.path` 系统属性指定。首次空库自动初始化，无需安装 SQLite 命令行工具。
- 手工执行迭代一脚本建立的旧库可能没有 user_version，程序会拒绝自动接管；不要通过重跑含清库命令的脚本解决。旧数据迁移需另行设计并先备份。
- 应用入口、后台任务与 EDT 切换、异常提示、可执行 JAR 和目标分辨率验证仍待实现。
