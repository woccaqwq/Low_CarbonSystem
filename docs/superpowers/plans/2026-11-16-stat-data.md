# Statistics Data Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 完成统计数据层：分类、月份、状态数量与统计卡片，供后续 StatService/GUI 使用。

**Architecture:** 不可变 StatQuery 表达时间范围和可选用户范围；SQL 独立聚合物品及流转再合并，避免联表倍增。
保留 StatDao 四个普通签名并补充范围查询、概览和 Connection 重载；所有查询只读，不管理调用方事务。

**Tech Stack:** Java 17、SQLite JDBC 3.47.1.0、JUnit 5.11.4、Maven。

**Spec:** 设计说明书第 4.2 章 StatDao；需求 FR-15/21 数据支持，原 item/flow_record/category/sys_user 表。

## Global Constraints

- 保留 countByCategory(): List<CategoryStat>、countByMonth(String year): List<MonthStat>、countItems(ItemStatus): int、countFlows(FlowStatus): int。
- 每个原方法补充 StatQuery 范围重载，新增 getOverview()/getOverview(StatQuery)，十个普通方法均提供 Connection 重载。
- StatCounts 不可变，保存三个物品状态及三个流转状态的 long 数量，总数从各状态求和。
- CategoryStat 按物品当前直接分类归组；全部分类含零值，不做父级重复汇总；有无分类数据时添加 null 编号的“未分类”组。
- 物品数按 item 记录计数，流转数按 flow_record 记录计数；分别聚合后连接，不能把多个意向乘进物品数。
- 月份统计固定返回请求年 12 个月，物品按 created_at，PENDING 按 created_at，DEAL/CANCELLED 按 finished_at（旧数据缺失时退回 created_at）。
- StatQuery 的日期为闭区间，按项目秒精度使用 00:00:00–23:59:59；可选 userId：物品限定发布人，流转限定任一交易方。
- 年份为 0001–9999 的四位 ASCII 数字，拒绝注入串；日期须在相同年份范围，from 不大于 to。
- 概览的物品/流转遵守范围；用户数/平均信用是当前账号快照，仅按 userId 限定、不按资源时间筛选，包含管理员与禁用用户。
- Connection 重载不提交、回滚、关闭连接；概览和每份分类/月报均使用单条查询以保证该结果内部一致。
- 不新增表，不实现 CSV、减碳估算或 StatService，不提交或推送。

## Review Focus

- 多意向不放大物品总数；分类删除后统计仍保留“未分类”。
- 月份以事件时间归属，跨年、闰日和日期边界正确；空年返回 12 个零值。
- 个人范围区分发布物品与参与流转，避免 OR 条件使时间过滤失效。
- 状态 null 表示总数；空库概览平均信用为 0.0，不出现 null/NaN。
- 统计看到同一外部事务的未提交更新，回滚后恢复；不能修改原数据。
