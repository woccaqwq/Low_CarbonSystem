# Flow Record Data Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 实现流转实体、状态机、DAO 与历史查询，为成员 2 的 FlowService 提供安全的同连接操作。

**Architecture:** 复用 BaseDao、DBUtil、TradeType 和 PageResult；用条件 SQL 执行状态更新，返回受影响行数。
五个冻结方法保留，补齐 cancelOtherPending、带原因取消、分页及买卖双方查询；所有操作提供 Connection 重载。

**Tech Stack:** Java 17、SQLite JDBC 3.47.1.0、JUnit 5.11.4、Maven。

**Spec:** 设计说明书第 4.2、5.3、8.3 章；需求 FR-10/11/12；原 flow_record 表与完成时间触发器。

## Global Constraints

- 保留 insert(FlowRecord)、findById(int)、updateStatus(int,FlowStatus)、existsPending(int itemId,int buyerId)、findByUser(int userId,FlowStatus) 五个普通签名。
- FlowStatus 为 PENDING/DEAL/CANCELLED，终态不可逆；实体 confirm()/cancel(reason) 只改内存。
- insert 仅创建 PENDING 且 finishedAt 为 null 的意向，不修改输入对象；同物品同买家重复待确认意向用单条条件 INSERT 拒绝。
- updateStatus 仅接受 DEAL/CANCELLED，从 PENDING 条件更新；同物品已有成交记录时不再更新为 DEAL，返回 0。
- cancelOtherPending(int itemId,int exceptFlowId) 只在保留记录属于该物品且已 DEAL 时取消其他 PENDING，不改其他终态。
- cancel(int flowId,String reason) 同时更新状态并将“取消原因：”附加到原 remark，不新增数据库字段，非空白原因必需。
- 查询我参与的记录含买家/卖家，null 状态不限；原 List 方法保留，补充 findByUser 分页、findByBuyer/ findBySeller 分页。
- 分页从 1 开始，每页 10–100，按 created_at DESC、flow_id DESC，offset 使用 long。
- 结果附加 itemTitle/sellerNickname/buyerNickname 当前展示投影，不改原始关联编号。
- DAO 不提交、回滚或关闭外部连接；Service 校验权限、卖家是否为物主、交易方式/物品状态，并检查更新行数后统一提交。
- 延续现有分支，不修改建表脚本、不实现 FlowService/GUI、不提交或推送。

## Review Focus

- 历史状态筛选必须作用于买卖双方的整个 OR 条件，避免遗漏括号。
- 重复意向与重复成交的单条 SQL 条件，历史取消后允许重新发起。
- 错误或尚未成交的 exceptFlowId 不应批量取消有效意向。
- 完成时间由既有触发器维护，终态重试不重置时间。
- 第二步物品写入失败和最后一步约束失败时，调用方回滚可恢复全部表。
